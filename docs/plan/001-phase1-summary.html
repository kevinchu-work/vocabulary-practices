Go-live checklist (your interactive steps)

1. Server

cd server
wrangler login                          # interactive OAuth
wrangler kv namespace create VOCAB      # paste the returned id into wrangler.toml
wrangler secret put MW_KEY              # your Merriam-Webster Learner's key
wrangler secret put API_TOKEN           # a long random string (also used by the app + page)
wrangler deploy
# verify Step 1's live criterion:
curl -H "Authorization: Bearer <API_TOKEN>" \
     "https://<your-worker>.workers.dev/lookup?word=voluminous"     # 2nd call = cache hit

Run this curl first — it is the gate. The offline tests mock MW, so they can't confirm the live learners URL path. If this returns real definitions, the server is good and any later problem is app-side. If it 404s or returns empty, it's the MW ref path or key — not the Mac app; don't debug Swift for it.

2. Mac app

cd mac-app
./build-app.sh
open build/SpellingLookup.app
# Grant Accessibility when prompted (System Settings ▸ Privacy & Security ▸ Accessibility)
# Click the menu-bar icon ▸ gear ▸ enter Worker URL + API token
# Select a word anywhere, press ⌘⇧L, then Save

3. Practice page

open https://<your-worker>.workers.dev/     # enter the same API token once

Known Phase-1 limitations (by design)

  • Single static bearer token — not real multi-user auth.
  • Hotkey fixed at ⌘⇧L (no in-app rebind UI).
  • Reading the selection uses synthetic ⌘C; the clipboard is saved and restored around it.
  • Unsigned dev build — macOS may re-prompt for Accessibility after a rebuild.
  • No audio pronunciation playback yet (MW provides the data — a Phase-2 add).
